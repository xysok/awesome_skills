# 月报生成工作流

**独立发布说明：本目录已包含运行所需公共 Python 模块。认证使用下述 lark-cli 官方登录流程；文末其他 lark-* 技能为外部参考，不随本仓库分发。任何真实写库须有用户授权，写入后按记录 ID 回读核实。**

## 适用场景

- "生成月报" / "本月月报" / "运行月报生成脚本"
- "月末汇总本月工作并输出下月规划"
- cron / 定时任务 no_agent 模式在每月最后一个工作日自动生成月报

## 前置条件

1. **lark-cli 已认证（user 身份）**，月报只需 Base 域：

   ```bash
   lark-cli auth login --domain base
   ```

2. **Python 3.8+**；预览主要使用标准库，正式写库的 LLM 提炼需要 `openai` SDK 和 `DR_LLM_API_KEY`。

3. **合格日报已写入同一张多维表格**（当前实现直接使用日报，而非先汇总周报），表字段：
   生成时间 / 报告日期 / 报告类型（"日报"）/ 工作小结 / 工作规划 / 工作小结（提炼）。

4. **配置**：环境变量（`DR_*`）或 `<scripts目录>/.env`（环境变量优先）。模板见
   [`templates/monthly_report.env.example`](templates/monthly_report.env.example)。
   关键项：`DR_BASE_TOKEN` / `DR_TABLE_ID`（月报与日报/周报共用同一张表）。

## 数据流

```
执行日（--date 或今天）
  └─► 守卫：必须是本月最后一个工作日，否则打印"跳过"并退出 0
        └─► base +record-list（page-size 200，一次全量）
              └─► 过滤 报告类型=周报 且 报告日期以 YYYY-MM 开头
                    └─► 按日期排序
                          └─► 抽取每篇周报【节标题】下的·条目：
                                工作小结【日程会议】→ 会议条目
                                工作小结【会话消息@】→ @消息条目（注意先于『会话消息』键判断，避免子串误吞）
                                工作小结【工作事项/待办】→ 事项条目
                                工作小结【问题解决】→ 卡点条目
                                工作规划【工作规划/下周/下月】→ 规划条目
                                      │
                                      ▼
                              按序去重（dict.fromkeys 保序）
                                      │
                                      ▼
  输出：【本月日程会议】N场 / 【本月工作事项】N项 / 【下月工作规划】N条
        └─► 默认写回多维表格（报告类型=月报，报告日期=执行日）；--preview 跳过
```

## 运行

```bash
# cron 入口（默认行为：最近工作日守卫 + 生成 + 写库）
python scripts/run_monthly_report.py

# 安全测试：仅预览不写库（--date 传本月最后一个工作日以通过守卫）
python scripts/run_monthly_report.py --date 2026-08-31 --preview

# 指定执行日（必须满足"本月最后工作日"，否则跳过）
python scripts/run_monthly_report.py --date 2026-08-31
```

**日期语义**：默认执行日 = 今天；`--date` 覆盖执行日（月窗口与守卫判断均用它）。
**写库语义**：月报**默认写库**（与日报/周报 skill 相反，那里写库需显式 `--write-base`）；
预览/测试请务必加 `--preview`。

## 输出结构

```
📅 工作月报 (YYYY年MM月)

【本月日程会议】N场
· 会议条目
【本月会话消息@】N条
· @消息条目（周报【会话消息@】按出现顺序去重；无则显示"本月没有@我的消息"）
【本月工作事项】N项
· 事项条目（周报工作事项按出现顺序去重）
【本月问题解决】N项
· 卡点条目（周报【问题解决】按出现顺序去重；无则显示"本月暂无未解决问题"）
【下月工作规划】N条
· 规划条目（各周报下周规划按序去重）
```

写库字段：工作小结 = 【本月日程会议】+【本月会话消息@】+【本月工作事项】+【本月问题解决】；工作规划 = 【下月工作规划】；报告日期 = 执行日；报告类型 = "月报"。

## 工作小结（提炼）列（默认步骤）

月报写库后**默认执行提炼**：把 `工作小结` 按主题聚类浓缩后填入同表 `工作小结（提炼）` 文本列
（该列需预先在表中创建，`text` 类型；与日报/周报共用同一列）。即月报写库完成后应紧接着按本节
方法提炼并 `+record-batch-update` 写入该列，不要只写脚本输出的五个字段。

### 触发

- "生成月报" / "运行月报生成脚本"（写库后默认提炼）
- "提炼月报内容" / "优化提炼方式" / "填入工作小结（提炼）"

### 提炼方法（2026-08 实践验证）

1. **先做周期判断，再拆主线**：从跨周条目中识别 3-6 条真正推进中的主线事项，先给出【周期总体判断】（最重要成果、主线所处阶段、协同重点、关键风险）；不得按日期、会议、消息或原始条目重述。
2. **固定主线**：产品研发 / 市场活动 / 临床活动 / 其他事项（按此顺序）；某主线无实质进展则整节省略。每条主线先写一句阶段判断，再将同一项目的测试、会议、沟通、跟进合并为 1-3 条推进叙事。
3. **每个主线事项必须闭环**：统一写 `主线事项（对象/阶段目标）→ 阶段进展（里程碑/决策/验证结果/影响）→ 问题与风险（阻塞/跨部门依赖/证据缺口/待确认）→ 推进规划（下月动作/预期交付/协同方/时间约束）`。没有明确阻塞才写“当前未见明确阻塞”；证据不足写“待确认”，不得虚构。
4. **价值线思维**：从“做了什么”转向“形成了什么成果、改变了什么、卡在哪里、接下来为何要推进”；以重要性、紧急性、变化、交接需求筛选取舍。
5. **规划不能独立罗列**：把周报中的下周/下月规划回填到对应主线事项；报告末尾另设【下月推进重点】，只保留 3-5 个跨主线优先动作，写清目标、交付/判断点和必要协同。
6. **简报语言与证据边界**：保留责任人、版本号、缺陷单/工单、医院/客户等可追溯信息；删除寒暄、备忘录和无实质内容。禁止“统一分析”“综述如下”等过程术语；月报约 1800-2600 字。

### 读写 Base 的操作要点

- 读月报全文：`lark-cli base +record-get --base-token <token> --table-id <id> --record-id <rid> --format json --as user`。
  返回为**矩阵**：记录在 `data.data`（一行数组），列顺序以 `data.fields` 为准，**勿按位猜字段**。
- 写入：`lark-cli base +record-batch-update --base-token <token> --table-id <id> --json '{"update_records":{"<rid>":{"工作小结（提炼）":"<text>"}}}' --as user`。
- Windows 注意：PowerShell 会把裸 `@file` 当 splatting 解析，传文件必须加引号 `--json "@payload.json"`；
  长中文文本用 Python 脚本（`PYTHONUTF8=1`）生成 UTF-8 JSON payload 文件再 `--json @file` 传入，避免 shell 转义与 GBK 乱码。

### 验证

- 更新后 `+record-get` 读回该列，核对字符数与关键条目；确认 `工作小结`/`工作规划` 原字段未被污染；验证完清理临时 payload 文件。

## 常见坑

1. **守卫机制**：非本月最后一个工作日 → 打印"跳过"并退出 0（cron 语义，不写库）。
   测试必须用 `--date <当月最后工作日>` 或测试守卫时用任意日期。
2. **写库是默认行为**：月报脚本没有 `--write-base`，预览/测试必须加 `--preview`，否则会落库。
3. **GBK/UTF-8**：Windows 下 `subprocess.run(text=True)` 默认按本地代码页（GBK）解码子进程输出，
   lark-cli 的 UTF-8 中文 JSON 会触发 UnicodeDecodeError 且被 `except` 吞掉 → 被误判为读取失败。
   脚本已统一 `encoding="utf-8", errors="replace"` 并 reconfigure stdio，勿改回。
4. **分页**：当前公共模块使用 `--limit 200 --offset N` 读取至 `has_more=false`，校验矩阵与记录 ID。
5. **无周报时 exit 1**：本月无周报记录 → 打印"本月暂无周报数据"并返回 1（不写库）。
6. **字段容错**：`报告类型` 可能是数组（如 `['周报']`）或字符串；`报告日期` 以 `YYYY-MM` 前缀匹配。
7. **依赖周报结构**：抽取依赖周报的【日程会议】【会话消息@】【工作事项/待办】【问题解决】【工作规划/下周/下月】节与
   ·条目格式（即 lark-workflow-weekly-report 的输出）；旧版无新小节周报会产出空列表 + 占位文案，不报错。
8. **去重保序**：`dict.fromkeys` 去重并保持首次出现顺序。
9. **噪声过滤**：聚合时剔除两类噪声——空标题会议（只有时间段，如 `（16:30-17:30）`）和
   无实质内容条目（含 `无待办输入`/`无实质工作内容`/`误发`/`致歉`/`发错` 等词的条目，如
   `事项：无待办输入`、`傅丽华：误发消息后致歉`）。过滤词表在脚本 `_NOISE_PATTERNS`，
   需增删关键词直接改脚本。`出差`/`会议室` 等有标题但无内容的日程**保留**。
   注意：该过滤只作用于月报聚合，源周报/日报里的原始条目不变。

## 验证

1. 用 `--date <当月最后工作日> --preview` 预览，核对【本月日程会议/工作事项/规划】条数与多维表格中本月周报一致；
2. 抽查某篇周报，确认同一会议/事项没有跨周重复；
3. 守卫自检：`--date <非月末日期>` 应打印"跳过"并退出 0；
4. 月末正式运行时，退出码 0 且 stderr 出现 `[OK] 已写入多维表格: <日期>`。
