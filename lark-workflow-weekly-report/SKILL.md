# 周报生成工作流

**独立发布说明：本目录已包含运行所需公共 Python 模块。认证使用下述 lark-cli 官方登录流程；文末其他 lark-* 技能为外部参考，不随本仓库分发。任何真实写库须有用户授权，写入后按记录 ID 回读核实。**

## 适用场景

- "生成周报" / "本周周报" / "运行周报生成脚本"
- "汇总本周工作并输出下周规划"
- cron / 定时任务 no_agent 模式每周五自动生成周报

## 前置条件

1. **lark-cli 已认证（user 身份）**，周报只需 Base 域：

   ```bash
   lark-cli auth login --domain base
   ```

2. **Python 3.8+**；预览主要使用标准库，正式写库的 LLM 提炼需要 `openai` SDK 和 `DR_LLM_API_KEY`。

3. **日报已写入同一张多维表格**（数据源 = lark-workflow-daily-report 的输出），表字段：
   生成时间 / 报告日期 / 报告类型（"日报"）/ 工作小结 / 工作规划。

4. **配置**：环境变量（`DR_*`）或 `<scripts目录>/.env`（环境变量优先）。模板见
   [`templates/weekly_report.env.example`](templates/weekly_report.env.example)。
   关键项：`DR_BASE_TOKEN` / `DR_TABLE_ID`（周报与日报共用同一张表）。

## 数据流

```
周五日期（--date 或自动算本周五）
  └─► 倒推本周一~五窗口（date-4 ~ date）
        └─► base +record-list（page-size 200，一次全量）
              └─► 过滤 报告类型=日报 且 报告日期 ∈ 本周
                    └─► 按日期排序
                          └─► 解析每篇日报的【】节与·条目（『会话消息@』必须先于『会话消息』判断）：
                                日程会议 → 会议条目（补 MM-DD 日期前缀）
                                会话消息@ → @消息条目
                                问题解决 → 卡点条目
                                待办     → 待办条目
                                其他【】节 → 工作条目
                                工作规划 ·条目 → 下周规划条目
                                      │
                                      ▼
                              按序去重（dict.fromkeys 保序）
                                      │
                                      ▼
  输出：【本周日程会议】N场 / 【本周会话消息@】N条 / 【本周工作事项】N项 / 【本周问题解决】N项 / 【下周工作规划】N条
        └─► --write-base：写回（报告类型=周报，报告日期=周五）
```

## 运行

```bash
# cron 入口（等价 gen_weekly_report.py --write-base）
python scripts/run_weekly_report.py

# 预览本周周报（不写库）
python scripts/gen_weekly_report.py

# 指定周（--date 必须传周五日期，如 2026-08-28）
python scripts/gen_weekly_report.py --date 2026-08-28 --write-base
```

**日期语义**：`--date` 必须是**周五**；缺省 = 当前自然周的周五（周六/周日运行也归本周）。

## 输出结构

```
📊 工作周报 (MM/DD-MM/DD)

【本周日程会议】N场
· 会议条目（带 MM-DD 前缀）
【本周会话消息@】N条
· @消息条目（各日报【会话消息@】按出现顺序去重；无则显示"本周没有@我的消息"）
【本周工作事项】N项
· 工作条目（各日报会话要点 + 当日待办，按出现顺序去重）
【本周问题解决】N项
· 卡点条目（各日报【问题解决】按出现顺序去重；无则显示"本周暂无未解决问题"）
【下周工作规划】N条
· 规划条目（各日报明日规划按序去重）
```

写库字段：工作小结 = 【本周日程会议】+【本周会话消息@】+【本周工作事项】+【本周问题解决】；工作规划 = 【下周工作规划】；报告日期 = 周五；报告类型 = "周报"。

## 工作小结（提炼）列（默认步骤）

周报写库后**默认执行提炼**：把 `工作小结` 按主题聚类浓缩后填入同表 `工作小结（提炼）` 文本列
（该列需预先在表中创建，`text` 类型；与日报/月报共用同一列）。即 --write-base 完成后应紧接着
按本节方法提炼并 `+record-batch-update` 写入该列，不要只写脚本输出的五个字段。

### 触发

- "生成周报" / "运行周报生成脚本"（--write-base → 写库后默认提炼）
- "提炼周报内容" / "优化提炼方式" / "填入工作小结（提炼）"

### 提炼方法（与月报 skill 同一套，2026-08 实践验证）

1. **先做周期判断，再写四条主线**：从全周期条目中识别 2-5 条真正推进中的主线事项，先给出【周期总体判断】（最重要结果、重心变化、待关注风险）；不得按日期、会议、消息或原始条目重述。
2. **固定主线**：产品研发 / 市场活动 / 临床活动 / 其他事项（按此顺序）；某主线无实质进展则整节省略。每条主线先写一句阶段判断，再将测试、会议、沟通、跟进等同一项目记录合并为 1-3 条推进叙事。
3. **每个主线事项必须闭环**：统一写 `主线事项（对象/目标）→ 阶段进展（结果/里程碑/影响）→ 问题与风险（阻塞/依赖/待确认）→ 推进规划（下周动作/交付或判断点/协同方）`。没有明确阻塞才写“当前未见明确阻塞”；证据不足写“待确认”，不得虚构。
4. **价值线思维**：从“做了什么”转向“产生了什么结果、改变了什么、下一步为何重要”；以重要性、紧急性、变化、交接需求筛选取舍。
5. **规划不能独立罗列**：把日报中的明日/下周规划回填到对应主线事项；报告末尾另设【下周推进重点】，只保留 3-5 个跨主线优先动作，写清目标、预期交付/判断点和必要协同。
6. **简报语言与证据边界**：保留责任人、版本号、缺陷单/工单等可追溯编号；删除寒暄、备忘录和无实质内容。禁止“统一分析”“综述如下”等过程术语；周报约 800-1200 字。

### 读写 Base 的操作要点

- 读周报全文：`lark-cli base +record-get --base-token <token> --table-id <id> --record-id <rid> --format json --as user`。
  返回为**矩阵**：记录在 `data.data`（一行数组），列顺序以 `data.fields` 为准，**勿按位猜字段**。
- 写入：`lark-cli base +record-batch-update --base-token <token> --table-id <id> --json '{"update_records":{"<rid>":{"工作小结（提炼）":"<text>"}}}' --as user`。
- Windows 注意：PowerShell 会把裸 `@file` 当 splatting 解析，传文件必须加引号 `--json "@payload.json"`；
  长中文文本用 Python 脚本（`PYTHONUTF8=1`）生成 UTF-8 JSON payload 文件再 `--json @file` 传入，避免 shell 转义与 GBK 乱码。

### 验证

- 更新后 `+record-get` 读回该列，核对字符数与关键条目；确认 `工作小结`/`工作规划` 原字段未被污染；验证完清理临时 payload 文件。

## 常见坑

1. **`--date` 必须是周五**：`get_week_range` 由周五倒推周一~五，传其他星期会得到错误的周窗口。
2. **GBK/UTF-8**：Windows 下 `subprocess.run(text=True)` 默认按本地代码页（GBK）解码子进程输出，
   lark-cli 的 UTF-8 中文 JSON 会触发 UnicodeDecodeError 且被 `except` 吞掉 → 被误判为读取失败
   （得到空记录）。脚本已统一 `encoding="utf-8", errors="replace"` 并 reconfigure stdio，勿改回。
3. **分页**：当前公共模块使用 `--limit 200 --offset N` 读取至 `has_more=false`，校验矩阵与记录 ID；读取异常不得当作空数据。
4. **无日报时 exit 1**：本周无日报记录 → 打印"本周暂无日报数据"并返回 1（不写库）。cron 可能据此
   判定任务失败，属设计行为。
5. **字段容错**：`报告类型` 可能是数组（如 `['日报']`）或字符串；`报告日期` 取前 10 字符比对日期。
6. **依赖日报结构**：解析依赖日报的 `【日程会议】/【待办】/【明日规划】` 节与 `·条目` 格式
   （即 lark-workflow-daily-report 的输出）；日报格式变化需同步此脚本。
7. **占位剔除**：`· 暂无` / `· 无` / `· 无会议` 等占位行在解析时剔除。
8. **去重保序**：跨天重复的会议/事项用 `dict.fromkeys` 去重并保持首次出现顺序。
9. **噪声过滤**：聚合时剔除两类噪声——空标题会议（只有时间段，如 `（16:30-17:30）`）和
   无实质内容条目（含 `无待办输入`/`无实质工作内容`/`误发`/`致歉`/`发错` 等词的条目，如
   `事项：无待办输入`、`傅丽华：误发消息后致歉`）。过滤词表在脚本 `_NOISE_PATTERNS`，
   需增删关键词直接改脚本。与月报 skill 同一套规则；只作用于聚合输出，源日报记录不变。
10. **日程日期**：聚合日程条目时按源日报的「报告日期」补 `MM-DD` 日期前缀
   （`_with_date`，形如 `（08-27 10:00-10:30）会议标题`）；已有日期前缀的条目不动。
   注意「报告日期」字段读回是日期时间类型（`2026-08-27T00:00:00.000+08:00`），
   取前 10 位再截 `MM-DD`，勿直接 `[5:]`。

## 验证

1. 先不带 `--write-base` 运行，核对【本周日程会议/工作事项/规划】条数与多维表格中本周日报一致；
2. 抽查某篇日报，确认同一会议/事项没有跨天重复；
3. 再 `--write-base` 写库，去多维表格核对记录（报告类型=周报、报告日期=周五）；
4. cron 入口 `run_weekly_report.py` 退出码 0 且 stderr 出现 `[OK] 已写入多维表格: <周五日期>`。
